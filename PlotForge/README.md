# PlotForge — 대지 배치 자동화 (Site Layout Automation)

> BimOn MCP 스위트 편입. MCP 서버명 `BimOn-PlotForge`.

그리드(격자) 기반 2D 사이트 디자인 자동화 도구. 대지를 그리거나 DXF로 불러오고,
사용자 정의 건물 타입·배치 규칙에 따라 자동/수동 배치하며, 도로를 자동 생성하고
여러 대안을 비교한다. **빌드 도구 불필요** — 정적 서버로 바로 실행.

## 실행

**`PlotForge.pyw` 더블클릭** (또는 `실행.bat`) — 창 없이 **시스템 트레이(알림 영역)에 아이콘으로 상주**한다.
브라우저는 자동으로 열린다. (Python 필요)
- **아이콘 더블클릭** → 브라우저 열기
- **아이콘 우클릭** → 메뉴(브라우저 열기 / 종료). **「종료」를 누르면 서버도 함께 종료**된다.
- 시작 시 "PlotForge 실행 중" 풍선 알림.

포트 변경: `실행.bat 8000` 또는 `PlotForge.pyw 8000`. 이미 그 포트에서 돌고 있으면 트레이를 새로 만들지 않고
브라우저만 연다(기존 서버 유지).

- `PlotForge.pyw`는 `http.server`를 백그라운드로 돌리고, `ctypes`로 Win32 `Shell_NotifyIcon`을 직접 호출해
  트레이 아이콘을 만든다 — **표준 라이브러리만, 추가 설치 없음**. 트레이 아이콘 `plotforge.ico`는 첫 실행 때
  코드로 생성된다(청록 바탕 + 2×2 필지 격자). 자가검증: `python PlotForge.pyw <포트> --selftest`(→ `TRAY OK`).
- `실행.bat`은 `pythonw`로 이 런처를 콘솔 없이 띄우는 얇은 진입점일 뿐이다(pythonw→`py -w`→python 폴백).

수동 실행도 가능 (ES 모듈이라 `file://`가 아닌 HTTP 서빙 필수):

```bash
# 프로젝트 폴더에서
python -m http.server 5178
# 브라우저에서 http://localhost:5178 열기
```

> `실행.bat`는 **UTF-8(BOM 없음) + CRLF 줄바꿈**으로 저장되며, 상단 `chcp 65001`로 콘솔
> 코드페이지를 UTF-8로 맞춘다 (시스템 기본이 949든 65001이든 한글이 깨지지 않음).
> 편집 시 주의: ① **BOM을 넣지 말 것**(첫 줄 `@echo off`가 깨져 실행 실패), ② **CRLF 유지**
> (LF만 남으면 cmd가 줄을 잘못 파싱해 echo 줄을 명령으로 실행하려다 실패한다).

## 사용 흐름

1. **대지 그리기**: 툴바 「대지 그리기」 → 캔버스 클릭으로 정점 추가 → 「대지 완성」(또는 더블클릭).
   또는 「DXF 불러오기」로 도면 임포트(면적 최대 폴리라인을 대지로 채택).
2. **셀 크기** 설정(월드 단위) → 대지가 격자로 분할됨.
3. **건물 타입 추가**: 이름 + 가로×세로(셀 수) + 색.
4. **배치 규칙 추가**(건물 타입에 종속, 「규칙」 탭 → 「+ 새 규칙」 모달에서 편집):
   | 종류 | 내용 |
   |---|---|
   | 도로/경계 인접 | 도로(도로망 모드) 또는 경계에서 N셀 이내 |
   | 세트백 | 도로/경계에서 N셀 이상 이격 |
   | 거리 범위 | 기준 타입과 최소~최대 셀 거리 (최소만=이격, 최대만=인접) |
   | 인접 개수 | N셀 이내 기준 타입 개수를 최소~최대로 제한 (상한=즉시 차단, 하한=최종 검증 표시) |
   | 방향 배치 | 기준 타입의 동/서/남/북쪽 N셀 이내 |
   | 행/열 정렬 | 기준 타입과 같은 행 또는 열에 정렬 |
   | 방위 개방 | 건물의 지정 방향 전면 N셀 비움 (일조·조망) |

   각 규칙은 hard(필수)/soft(선호, 가중치 1~100 지정)로 설정. hard는 양방향 보장 —
   나중에 배치되는 건물이 기존 건물의 개방구역·이격·인접상한을 침범할 수 없음.
   구형 저장본의 이격(gapFrom)/인접(adjacentTo) 규칙은 로드 시 「거리 범위」로 자동 변환.
   툴바의 **건폐율≤ %** 입력 시 사이트 전체 건폐율 상한이 자동/수동 배치 모두에 적용됨.
5. **배치 순서** 구성(건물 타입의 「순서+」).
6. **자동 배치**: 그리디 배치 → 미배치 시 재편 후 재시도 → **시뮬레이티드 어닐링**(전역 재배열)
   → 미배치 재시도 → 언덕오르기 마무리. hard 규칙은 전 과정에서 유지.
   서로 다른 대안 2개 추가 생성. 또는 건물 타입의 「배치」로 **수동 배치**(초록칸=가능, 노란 점선=추천 위치).
7. **이동**: 「선택/이동」으로 배치된 건물 드래그(격자 스냅, 충돌 방지, 최적위치 추천 표시).
8. 수동 배치/이동 시 **배치 가능성 검증** 패널에 남은 건물 배치 가능 여부 표시.
   순차 시뮬레이션 방식 — 앞 건물의 가상 배치가 뒤 건물 검사에 반영됨.
9. **도로 생성**: 빈 셀 경로 탐색으로 건물→대지경계 도로망 자동 생성.
   2개 이상 건물이 공유하는 구간은 **주도로**(밝은 색)로 구분되며 **폭 2셀로 자동 확폭**
   (진행방향과 수직인 빈 셀을 추가, 건물에 막힌 구간은 유지).
9-1. **도로 우선 모드** (「도로망 생성」 토글): 도로망을 먼저 깔면 건물은 남은 필지에만
   배치되고, **도로인접/세트백 규칙이 실제 도로 기준**으로 동작하며 진입로가 도로망에
   자동 접속됨. 간격은 최대 건물 치수+3(4~12셀)로 자동 결정.
   도로망은 대안 간 공유(사이트 인프라)이며 대지·셀크기 변경 시 초기화됨.
   - **패턴 선택**: 빗살형(메인+가지) / 격자형(양축) / 루프형(외곽 순환 + 진입 스퍼).
     도로망이 있는 상태에서 패턴을 바꾸면 즉시 재생성.
   - **진입점 지정**: 「진입점」 도구로 대지 경계를 클릭하면 가장 가까운 경계셀로 스냅.
     빗살형은 메인도로가 진입점을 지나고, 루프형은 진입점→루프 연결 스퍼가 생김.
     미지정 시 대지 질량중심에 가장 가까운 경계셀 자동 선택(루프형).
10. **대안 비교**: 대안 목록에 지표(배치 수, 충전율, 점수, hard 위반, 건폐율 초과) 표시.
11. **저장/불러오기**: JSON 다운로드/업로드 + localStorage 자동저장(새로고침 시 복원).
12. **되돌리기/다시**: Ctrl+Z / Ctrl+Y(또는 Ctrl+Shift+Z), 툴바 버튼. **PNG 내보내기**: 현재 캔버스를 이미지로.
13. **DXF 내보내기**: 활성 대안을 R12 호환 DXF로 출력. 레이어 SITE(대지)/ROAD(도로, 행 단위
    병합)/BLDG_타입명(건물)/ANNO(라벨). 자체 임포트 파서와 왕복 가능.

## 구조

| 파일 | 역할 |

| `index.html`, `styles.css` | 앱 셸 · 탭 패널(대안/건물·순서/규칙/검증) · 규칙 편집 모달 |

| `src/app.js` | 상호작용 · 패널 UI · 툴 로직 |

## 좌표계

- **월드좌표**: 대지 실좌표(DXF 단위). 대지 폴리곤·DXF가 이 좌표.
- **셀좌표** `(c, r)`: 격자 인덱스. 건물은 셀 단위(2×2 = 2셀×2셀)로 점유.
- **화면좌표**: 캔버스 픽셀. `render.js`의 `fitView`가 대지를 캔버스에 맞춰 변환.

## 데모 시나리오 (LNG 복합화력 Plot Plan)

툴바 「데모」 → LNG 복합화력 발전소 예제가 로드된다 (500×350m 부지, 2m/셀, 타입 46종,
Power Block 등 블록 3개, m 단위 규칙 38개, Tie-in 앵커 5개, 풍향 SW, 클리어런스 매트릭스).
사용 순서: ① 「도로망 생성」(루프·폭 8m·링 5m 사전설정) → ② 「자동 배치」(약 9초).
결과: Flare는 다운윈드 최외곽, K.O드럼은 Flare↔PB 중간, Admin은 3중 이격 준수 등 위반 0.
이 파일(demos/lng-ccpp.json)이 곧 "프로젝트 = 데이터" 원칙의 예시다 — 코드에는 발전소 내용이 없다.
대형 격자(2만 셀 초과)에서는 대안이 1개씩 생성되고 배치가능성 검증은 검증 탭의 버튼으로 실행한다.

## MCP 연동 (Claude가 직접 조작) — `BimOn-PlotForge`

프로젝트 루트의 `.mcp.json`에 MCP 서버 `BimOn-PlotForge`가 등록되어 있어, **Claude(데스크톱/코드)에서**
Claude가 도구로 직접 프로젝트를 구성·실행할 수 있다 (`tools/mcp_server.py` — 순수 Python 3.8, 의존성 없음).
도구 접두사는 `plotforge_*` (BimOn 스위트의 `BimOn-Revit`/`BimOn-Forma`와 동일한 `BimOn-<앱>` 규칙).

| 도구 | 기능 |
|---|---|
| plotforge_execute_script | **열린 앱에서 JS 실행 후 결과 반환** (Revit/AutoCAD `execute_script` 대응, 기본 도구) |
| plotforge_new_project | 부지 생성 (m 단위, 셀 크기) |
| plotforge_add_type / add_block | 건물 타입·블록(멤버 상대좌표 m) 추가 |
| plotforge_add_rule | 규칙 11종 추가 (거리 전부 m — 이름으로 타입/앵커 참조) |
| plotforge_set_sequence / set_wind / add_anchor / add_clearance / set_roads | 순서·풍향·앵커·클리어런스·도로 파라미터 |
| plotforge_run_layout | **도로망+자동배치 실행** — 열린 앱의 실제 JS 엔진을 구동(재구현 없음), 화면 즉시 반영·지표 반환 |
| plotforge_status / plotforge_summary | 연결/프로젝트 현황 |

**동작 방식 — 라이브 앱 브리지 (BimOn 스위트 공통 모델):** Revit/AutoCAD/Forma가 애드인으로 살아있는
앱에 직접 명령하듯, PlotForge도 **열려 있는 앱을 실시간으로 직접 조작**한다. 헤드리스 브라우저도,
파일 폴링도, 켜고 끄는 토글도 없다.
- MCP 서버(파이썬)가 **WebSocket 브리지 `ws://localhost:5179`** 를 백그라운드로 호스팅한다
  (순수 stdlib — `hashlib`/`base64`/`struct`/`socket`, 무의존성 유지).
- 열려 있는 앱이 클라이언트로 접속한다(자동 재접속). 도구 호출 → 브리지로 코드 전송 →
  살아있는 앱 컨텍스트에서 실행 → 결과를 동기 회수. 앱이 곧 단일 진실이라 별도 파일이 필요 없다.
- Revit 애드인은 앱 안에서 리스너를 열지만 브라우저는 소켓을 못 열어 **접속 방향만 반대**다.
  사용자 경험은 동일: 앱을 열어두면 Claude가 조작한 결과가 즉시 화면에 반영된다(되돌리기 Ctrl+Z).

**사용 절차:** ① `실행.bat`로 앱을 연다(정적 서버 :5178 — 파일 서빙 담당) → ② Claude에서
`BimOn-PlotForge` 도구를 호출한다. 툴바 **「🔗 Claude」** 배지가 연결 상태(연결됨/대기)를 표시하며,
클릭하면 재접속을 시도한다. MCP 서버가 아직 안 떠 있으면 앱이 2초 간격으로 조용히 재시도한다.
앱이 열려 있지 않으면 도구는 "앱을 여세요" 오류를 반환한다(Revit이 열려 있어야 하는 것과 동일).

포트는 환경변수로 조정한다: `PLOTFORGE_WS_PORT`(기본 5179), `PLOTFORGE_APP_URL`(기본 http://localhost:5178).
앱 쪽 브리지 주소는 `window.__PF_BRIDGE_URL`로 덮어쓸 수 있다.

## 테스트

엔진/기하/DXF 회귀 테스트가 `tests/selftest.js`에 있다. 앱 페이지의 브라우저 콘솔에서:

```js
import('./tests/selftest.js').then(m => m.run())
```

25개 케이스(기하·격자·규칙 6종·양방향 검증·건폐율·자동배치 재현성·순차 검증·도로 3패턴·DXF 왕복)를
console.table로 출력한다. UI 플로우(그리기·폼·드래그·Undo)는 별도 수동/세션 테스트로 확인.

## 향후 확장 (미구현/개선 여지)

- 규칙 확대: 조망/이격거리(m 단위), 용적률(층수 도입 시), 특정 도로변 지정 세트백.
- 어닐링 파라미터(반복수/온도) UI 노출, 대안 수 설정.
- 도로망: 막다른길/교차부 정리, 루프형 링 깊이 조절 UI.
- 층수 개념 도입 + 용적률 규칙.
- DXF: 좌표 Y축 방향이 CAD와 반대(캔버스 기준). 임포트-내보내기 왕복은 일관되나
  외부 CAD 도면과 합칠 때는 Y 반전 필요할 수 있음.
- Node 도입 시 Vite 빌드 → Electron 데스크톱 앱 또는 AutoCAD DXF 브리지.
